# Планшет как сервер 24/7 (Termux)

Этот вариант — вместо гоняющей круглосуточно основной машины: мост и `opencode`
живут на планшете, телефон (или второй планшет) подключается как клиент.
Проверено на бумаге, не на железе: risky step один — сборка `node-pty`
(скрипт сам проверяет и честно падает с подсказкой).

## Что понадобится

- Планшет ARM64, Android 8+, постоянно на зарядке и в домашнем WiFi.
- **Termux с F-Droid** (версия из Play Store заброшена и не подойдёт).
- Приложения-компаньоны: **Termux:API** (wake-lock) и желательно **Termux:Boot**
  (автозапуск после перезагрузки). Ставятся с F-Droid.
- ~2 ГБ свободного места (репо + `node_modules` + тулчейн для сборки `node-pty`).
- Голосовой ввод (STT) на планшете **не включаем** — слабый CPU, модель не влезет.
  Мост это переживёт: воркер стартует только по первому `/stt`.

## Шаг 0. Android: не давать системе убивать Termux

1. Настройки → Батарея → Termux → **«Не оптимизировать»** (без этого Doze
   прибьёт мост ночью — это главная причина «утром не коннектится»).
2. Настройки → WiFi → держать WiFi включённым в спящем режиме.
3. Планшет на зарядке 24/7 греет и пучит батарею. Если в прошивке есть лимит
   заряда (как Smart Charge на ноутбуках) — включи 60–80%. Нет — хотя бы не
   держи под подушкой, и раз в месяц давай батарее цикл.

## Шаг 1. Termux: пакеты и мост

```bash
# перекинь termux-setup.sh из tablet/ этого репо на планшет (adb, флешка, scp…)
bash termux-setup.sh
```

Скрипт сам: обновит пакеты, поставит `nodejs-lts python clang make git openssh`,
склонирует репо, сделает `npm install`, проверит/соберёт `node-pty`, создаст
`config.json` (`defaultCwd`/`projects` = `$HOME` — поправь под себя),
возьмёт wake-lock и запустит `node server.js`. QR и код сопряжения — в выводе.

## Шаг 2. opencode на планшете

Мост — только транспорт; сам агент нужен отдельно. Варианты (оба живые):

- **Hope2333/opencode-termux** — готовые пакеты актуального opencode под ARM64
  (есть нативная zero-glibc сборка). Рекомендуется.
- **retired64/opencode-termux** — установка одной строкой, тянет glibc + официальный бинарь.

Проверь: `opencode --version`. Бинарь должен быть в `PATH`, иначе мост не сможет
стартовать сессии (`opencodeCommand` в `config.json` — полный путь при нужде).

## Шаг 3. Сопряжение телефона

Как обычно: IP планшета в домашней сети + порт `8890` (UFW на планшете нет —
root не нужен, порты >1024 слушаются без привилегий). QR/код — из Termux.
mDNS на Android может не взлететь — тогда сработает UDP-маяк; в крайнем случае
вбей IP руками (узнать: `ip -4 addr show wlan0`… интерфейс смотри по факту:
`ip -4 route get 8.8.8.8`).

## Шаг 4. Доступ вне дома

Тот же сценарий, что на ПК: `opencode-mobile --device` → `i` (бинарь
`bridge/bin/opencode-tunnel` в репо **не лежит** — собери на ПК и закинь на
планшет: это обычный aarch64-файл, `libopencode-tunnel.so` не нужен, нужен сам
`opencode-tunnel`). Либо подожди CI-артефакт. Дальше: один коннект по LAN за
тикетом → уход на p2p.

## Шаг 5. Автозапуск после перезагрузки (Termux:Boot)

Положи исполняемый скрипт в `~/.termux/boot/start-bridge`:

```bash
#!/data/data/com.termux/files/usr/bin/bash
termux-wake-lock
exec node $HOME/opencode-bridge/bridge/server.js >> $HOME/bridge.log 2>&1
```

(`chmod +x`, Termux:Boot должен быть установлен, а его автозапуск разрешён
в настройках Android.)

## Шаг 6 (опционально). Удалённое администрирование

На планшете подними `sshd` (`pkg install openssh; sshd`, порт по умолчанию
8022) — с ПК заходишь `ssh -p 8022 <ip-планшета>`, дальше всё как дома:
`opencode-mobile devices/revoke/internet`, логи, рестарт.

## Честные ограничения

- Мощность: планшетный CPU тянет мост и 1–3 сессии легко; тяжёлые репо/LSP —
  медленно, но терпимо. STT не включать.
- Память: мост ~70 МБ + сессии; 4 ГБ ОЗУ планшета хватит с запасом.
- Планшет-клиент (Lenovo) и планшет-сервер — разные устройства: в приложении
  просто будет два «компьютера», переключаются в списке.
- Путь не обкатан на реальном железе — первый прогон делай рядом с розеткой
  и держи Termux на глазах; все падения скрипт показывает русским текстом.
