# Claude Bridge — архитектура и полное техническое описание

Резюме всей программы: зачем она нужна, из чего состоит, как устроен каждый
компонент, какие протоколы связывают части, какие функции доступны пользователю
и как обеспечивается безопасность. Документ отражает фактическое состояние кода
(server.js, keeper.js, attach.js, stt.py, tunnel/src/main.rs, Android-модуль,
web-интерфейс) на июль 2026.

---

## 1. Что это и зачем

**Claude Bridge** — связка «нативное Android-приложение + Node.js-мост на ПК»,
которая **зеркалирует и позволяет управлять сессиями Claude Code**, запущенными
в терминале компьютера, прямо со смартфона.

Ключевая идея: Claude Code продолжает работать на ПК (со всем доступом к
файловой системе, git, тулчейнам), а телефон становится вторым «терминалом» той
же самой сессии. То, что печатается на ПК, видно на телефоне и наоборот — это
одна общая PTY, а не отдельные копии.

Основные пользовательские сценарии:

- **Зеркало сессии.** Запустил `claude-mobile` на ПК — та же сессия открылась на
  телефоне; можно печатать с обоих устройств.
- **Полностью удалённый запуск.** С телефона можно создать новую сессию Claude
  Code в разрешённом проекте, не подходя к компьютеру.
- **Push-уведомления.** Когда Claude ждёт разрешения на действие или закончил
  ответ — на телефон приходит системное уведомление; можно ответить «Да / Всегда
  / Нет» прямо из шторки.
- **Голосовой ввод.** Надиктовать сообщение Claude: запись — на телефоне,
  распознавание (faster-whisper) — на ПК.
- **Работа вне дома.** Если телефон ушёл из домашней сети, связь автоматически
  переключается на p2p-туннель через интернет (iroh, QUIC), без проброса портов
  и без VPN.

Приоритеты проекта (сквозные ограничения при разработке): **не ломать рабочую
функциональность**, держать секреты в режиме `0600`, применять принцип
fail-closed в спорных местах безопасности, аккуратно перепроверять код.

## 2. Топология

```
   ┌─────────────────────────── ПК (Linux) ────────────────────────────┐
   │                                                                    │
   │  claude-bridge.service (systemd --user)                            │
   │     └─ node server.js  ── HTTPS/WSS :8790  (0.0.0.0, LAN)          │
   │            │                UDP  :8791  (маяк обнаружения)          │
   │            │                WSS  :8792  (loopback, вход туннеля)    │
   │            │                                                        │
   │            ├─ keeper.js (по одному на сессию) ── unix-сокет ── PTY  │
   │            │        └─ claude … (процесс Claude Code)               │
   │            │                                                        │
   │            ├─ stt.py (faster-whisper, постоянный воркер)            │
   │            │                                                        │
   │            └─ claude-tunnel listen (Rust, iroh p2p)                 │
   │                     ▲ QUIC/iroh ALPN "claude-bridge/1"              │
   │  claude-mobile (attach.js) ── WSS :8790 (loopback) ── тот же мост   │
   │  bridge-hook.sh ── POST /hook :8790 (loopback)                      │
   └────────────────────────────────┼───────────────────────────────────┘
                                     │  LAN (WiFi)          Интернет (p2p)
                                     ▼                           ▼
   ┌──────────────────────────── Телефон (Android) ─────────────────────┐
   │  BridgeService (foreground)                                        │
   │     ├─ OkHttp WSS ── мост :8790  (пиннинг сертификата)              │
   │     ├─ NSD (mDNS) + UDP-проба :8791  ── находит мост в сети         │
   │     └─ claude-tunnel connect (libclaudetunnel.so) ── p2p до ПК      │
   │  LocalGateway (127.0.0.1)                                          │
   │     ├─ :38471 статика UI из assets APK                             │
   │     └─ :38472 ws-прокси → TLS → мост (подставляет токен)           │
   │  MainActivity (WebView + xterm.js) ── http://127.0.0.1:38471       │
   └────────────────────────────────────────────────────────────────────┘
```

Два физических пути до моста:

1. **LAN (WiFi):** телефон нашёл ПК по mDNS/UDP, подключается напрямую к
   `wss://<ip-пк>:8790`. Приоритетный путь — самый быстрый.
2. **Интернет (p2p):** если ПК не виден в локальной сети, поднимается пара
   `claude-tunnel connect` (телефон) ↔ `claude-tunnel listen` (ПК) поверх iroh;
   телефон подключается к `wss://127.0.0.1:<локальный порт туннеля>`, а сайдкар
   пробрасывает байты по QUIC на loopback-порт `8792` моста.

В обоих случаях транспорт для WebSocket — **TLS с пиннингом самоподписанного
сертификата** моста; интернет-туннель добавляет ещё один слой (шифрование iroh),
но пиннинг TLS остаётся сквозным (end-to-end от WebView до моста).

## 3. Мост на ПК (каталог `bridge/`)

### 3.1 `server.js` — ядро (≈1050 строк)

Единый Node.js-процесс. Слушает три сокета:

| Сокет | Адрес | Назначение |
|-------|-------|-----------|
| Основной HTTPS/WSS | `CONFIG.host:8790` (0.0.0.0) | LAN + localhost: UI, WS, /pair, /stt, /hook, /health |
| UDP-маяк | `*:8791` | ответ на broadcast `CLAUDE_BRIDGE?` |
| Туннельный HTTPS/WSS | `127.0.0.1:8792` | трафик из интернет-туннеля (тот же обработчик) |

Оба HTTPS-сервера используют **один и тот же** `httpHandler` и один и тот же
TLS-контекст; различаются только `localPort`, по которому код отличает «настоящий
локальный» трафик от туннельного.

#### Конфигурация (`config.json`)

```json
{
  "port": 8790, "host": "0.0.0.0",
  "claudeCommand": "claude", "claudeArgs": [],
  "defaultCwd": "~/projects",
  "projects": ["~/claude-bridge", "~/projects"],
  "env": { "HTTP_PROXY": "...", "HTTPS_PROXY": "...", "NO_PROXY": "..." },
  "scrollbackBytes": 1048576,
  "sttPython": "python3.11", "sttModel": "large-v3", "sttLanguage": "ru"
}
```

- `projects` — «белый список» каталогов, в которых **телефон** может запускать
  сессии (локальные клиенты не ограничены).
- `env` — окружение, наследуемое каждой сессией Claude (в т.ч. прокси). Файл
  жёстко чинится в `0600` при старте, т.к. может содержать секреты.

#### TLS и отпечаток

При первом запуске генерируется самоподписанный сертификат
(`openssl req -x509 rsa:2048`, срок 10 лет, CN=claude-bridge) в `certs/`.
Каталог `certs/` чинится в `0700`, `key.pem` — в `0600` (openssl под umask 022
создаёт его `0644`). Публичный **отпечаток** — SHA-256 от DER-кодированного
сертификата (`FINGERPRINT`). Телефон пиннит именно этот отпечаток; он же —
идентификатор компьютера в приложении.

#### Аутентификация и доверие

Три уровня:

1. **`isLocal(req)`** — «это сам ПК». Требует:
   - remoteAddress == loopback (`127.0.0.1` / `::1` / `::ffff:127.0.0.1`);
   - соединение пришло на **основной** порт (`localPort === CONFIG.port`) —
     трафик из туннеля (порт 8792) сюда не попадает;
   - **UID процесса на том конце сокета == UID моста** (`SELF_UID`).

   UID определяется функцией `peerUid()` через `/proc/net/tcp`: ищется строка с
   **полным совпадением 4-кортежа** (оба IP и оба порта, крест-накрест
   local↔remote) и состоянием `ESTABLISHED (01)`. Полное сравнение исключает
   подмену UID чужим процессом, открывшим соединение с тем же эфемерным портом на
   другой loopback-адрес; `ESTABLISHED` отсекает `TIME_WAIT`-призраки. Если UID
   определить нельзя (не-POSIX, контейнер, hardened /proc) — **fail-closed**,
   доверие не выдаётся.

   Локальным клиентам (`claude-mobile`, десктоп-браузер) и хукам этого достаточно
   — токен не нужен.

2. **Токен устройства** — постоянный `crypto.randomBytes(24).toString('hex')`,
   выдаётся телефону при сопряжении, хранится в `pairings.json` (`0600`).
   Сверяется за **постоянное время** (`crypto.timingSafeEqual`) в
   `deviceByToken()`, чтобы не утекать по таймингу. Токен передаётся либо в
   query `?token=…`, либо в cookie `bridgeToken=…`.

3. **`authed(req, url)`** = `isLocal(req) || deviceByToken(...)`.

Публичный `deviceId` — первые 12 hex-символов SHA-256 от токена: по нему можно
ссылаться на устройство (в UI, при отзыве), не раскрывая сам токен.

#### Сопряжение — `POST /pair`

- Доступно **только по основному порту** (не через туннель — туннель поднимается
  уже после сопряжения).
- Код сопряжения — `crypto.randomBytes(3)` (6 hex-символов, upper-case), живёт
  **10 минут**, генерируется при старте моста и по запросу `claude-mobile --qr`.
- **Одноразовость:** при верном коде `expiresAt` сразу обнуляется — одним
  подсмотренным кодом нельзя сопрячь несколько устройств.
- **Защита от перебора** — по IP (`pairGuard`): 5 неверных попыток → блокировка
  `/pair` для этого адреса на 15 минут (не глобально, иначе один злоумышленник
  заблокировал бы сопряжение для всех). Есть бэкстоп на рост карты (>4096 →
  очистка).
- Тело запроса ограничено 4 КБ. Код сверяется за постоянное время.
- В ответ отдаётся: `token`, `fingerprint`, `port`, `hostname`, `nodeTicket`
  (p2p-адрес, если интернет включён), `internet`.

#### Управление сессиями

Каждая сессия — **отдельный процесс `keeper.js`**, владеющий PTY. Мост общается
с ним через unix-сокет в `~/.claude-bridge/sessions/<id>.sock` (каталог `0700`).
Такое разделение — принципиальное: **перезапуск моста не убивает Claude Code**.

- `createSession({cwd, command, args, title, local})`:
  - `id` = `s<seq>-<6 hex>`;
  - **команду** (бинарь) выбирает только локальный клиент; телефон всегда
    запускает настроенный `claude` (нельзя запустить `/bin/sh`);
  - **аргументы** (`--resume`, `--dangerously-skip-permissions` и т.п.) телефон
    задаёт сам — это штатные опции, а сопряжённое устройство и так имеет полный
    интерактивный контроль над PTY;
  - **каталог** телефона ограничивается `remoteCwd()`: `realpath` (снимает
    симлинки, чтобы ссылка внутри проекта не вывела наружу) + проверка
    `isUnderAllowedRoot`; иначе — `defaultCwd`;
  - окружение (`process.env` + `CONFIG.env` + `CLAUDE_BRIDGE_SESSION`,
    `FORCE_COLOR=3`) **не пишется в meta-файл** (секреты не остаются на диске),
    а передаётся keeper-у через сам процесс;
  - keeper запускается `detached + unref`, `stdio: 'ignore'`.
- `restoreSessions()` при старте: перечитывает `*.json`, для каждого проверяет
  наличие `.sock` (если сокета нет — keeper умер, meta удаляется) и
  переподключается.
- **Лимиты ресурсов:** `MAX_SESSIONS` (по умолчанию 24), не более 10 создаваемых
  сессий в минуту на устройство (`rateAllowCreate`).
- **Scrollback:** мост держит буфер вывода (по умолчанию 1 МБ на сессию,
  `CONFIG.scrollbackBytes`), обрезая старое; при `attach` новый клиент получает
  весь буфер, а keeper дублирует его у себя.

Политика размера PTY: **«размер следует за тем, кто печатает»**
(`session.lastInput`); подключение зрителя размер не меняет — иначе два клиента с
разными экранами дёргали бы PTY туда-сюда.

#### Голосовой ввод — `POST /stt`

- Требует `authed`.
- Очередь ограничена (`sttMaxQueue`, по умолчанию 4) → 503 при переполнении.
- Загрузка пишется **сразу на диск** (`0600`, `os.tmpdir()`), не в память;
  лимит 20 МБ → 413. При обрыве загрузки временный файл удаляется.
- Распознавание — постоянный воркер `stt.py` (модель грузится один раз);
  таймаут 180 с; ошибки логируются на ПК, клиенту — обобщённый текст без
  внутренних путей. Временный файл удаляется в `finally`.

#### Хуки Claude Code — `POST /hook`

- Требует **`isLocal`** (хук вызывается на самом ПК).
- Принимает JSON события Claude (`hook_event_name`, `message`, …) + заголовок
  `X-Bridge-Session`.
- Маппинг событий в статус сессии для вкладок:
  `UserPromptSubmit/PostToolUse → working`, `Notification → waiting`,
  `Stop → idle`.
- Для `Notification` и `Stop` рассылает клиентам `notify` (это push на телефон).
- Отдельное событие `status` шлётся по `working`, чтобы телефон гасил устаревшие
  уведомления даже для сессий, которых уже нет в списке.

#### Интернет-доступ (p2p iroh)

- Флаг `internet.json` (`{ "enabled": true }`), переключается только с самого ПК
  (`claude-mobile --device` → `i`).
- При включении запускается сайдкар `bin/claude-tunnel listen` с:
  - `--target 127.0.0.1:8792` (loopback-порт моста для туннеля);
  - `--secret-file certs/iroh.key` (постоянный ключ → стабильный NodeId);
  - `--allow-file certs/tunnel-allow.txt` (**allowlist** NodeId сопряжённых
    устройств).
- `writeAllowFile()` пишет в allowlist NodeId всех сопряжённых устройств
  (валидируя формат `^[0-9a-f]{64}$`, файл `0600`). Телефон регистрирует свой
  NodeId по LAN через защищённый WS (сообщение `registerNode`).
- Мост парсит JSON-события сайдкара из stdout (`ready` с ticket/node_id, `conn`,
  `path`, `close`) и рассылает статус клиентам (`internet`-сообщение).
- Перед стартом убивает бесхозные туннели прошлых запусков
  (`pkill -f "<bin> listen"`, без shell). При падении сайдкара — авто-рестарт
  через 3 с. При выходе моста туннель гасится (иначе при `KillMode=process`
  переживёт рестарт и задвоит iroh-endpoint).

#### Отзыв устройства — `revokeDeviceById`

Удаляет устройство из `pairings.json`, переписывает allowlist, **немедленно
рвёт его WS-соединения** (`close(4401, 'revoked')`) и **перезапускает туннель**,
чтобы сбросить живые p2p-соединения отозванного узла (allowlist проверяется при
установке; плюс сайдкар перепроверяет его на каждый новый поток).

#### Обнаружение в сети

- **mDNS** (`bonjour-service`): публикует сервис `claude-bridge` с TXT-записью
  `fp=<отпечаток>`.
- **UDP-маяк** (порт 8791): на broadcast `CLAUDE_BRIDGE?` отвечает unicast'ом
  `{claudeBridge, port, host, fp}`. **Отвечает только на приватные адреса**
  (RFC1918 / link-local / loopback — `isPrivateAddr`), чтобы не служить
  рефлектором и не раскрывать hostname+отпечаток наружу. UDP надёжнее mDNS в
  «замусоренных» сетях.

#### Заголовки безопасности статики

CSP как HTTP-заголовок (не `<meta>`, т.к. `frame-ancestors` в мете
игнорируется): `default-src 'self'`, `script-src 'self'`, `connect-src` только
к loopback ws/wss, `object-src 'none'`, `frame-ancestors 'none'`, плюс
`X-Frame-Options: DENY`, `X-Content-Type-Options: nosniff`,
`Referrer-Policy: no-referrer`. Путь к статике защищён от traversal
(`path.normalize` + строгая проверка `startsWith(WEB_DIR + sep)`, разделитель
обязателен, чтобы сосед `web-secret` не прошёл префиксную проверку).

### 3.2 `keeper.js` — хранитель сессии (80 строк)

Отдельный процесс, переживающий перезапуск моста. Владеет одной PTY
(`node-pty`), слушает unix-сокет.

- Спавнит `meta.cmd meta.args` с `xterm-256color`, размером и cwd из meta;
  окружение берёт из `process.env` (переданного мостом), `meta.env` — только для
  совместимости.
- Держит собственный scrollback (лимит = `meta.scrollbackBytes`).
- Протокол по сокету — JSON-строки:
  - **вход** (мост → keeper): `{t:'in', d}`, `{t:'resize', cols, rows}`,
    `{t:'kill'}`;
  - **выход** (keeper → мост): `{t:'hello', buffer, cols, rows, pid}` при
    подключении, `{t:'out', d}` на каждый вывод PTY, `{t:'exit', code}`.
- При `onExit` рассылает `exit`, удаляет сокет и meta-файл, выходит через 200 мс.
- Каталог сессий на всякий случай чинится в `0700` (сокет keeper-а не имеет
  собственной аутентификации — доступ к нему = контроль над сессией).

### 3.3 `attach.js` (`claude-mobile`) — CLI на ПК (180 строк)

Локальный клиент моста; подключается к `wss://127.0.0.1:8790/ws`
(`rejectUnauthorized:false` — для localhost это безопасно, доверие даёт
`isLocal`).

Режимы:

| Команда | Действие |
|---------|----------|
| `claude-mobile [args…]` | новая сессия в текущем каталоге; все аргументы уходят `claude` |
| `claude-mobile -l` | список сессий |
| `claude-mobile -a [id]` | подключиться к сессии (без id — к последней живой) |
| `claude-mobile --device` | TUI доверенных устройств + вкл/выкл интернет-доступа + отзыв |
| `claude-mobile --qr` | показать QR-код сопряжения (свежий код на 10 минут) |

- В интерактивном режиме переводит stdin в raw, зеркалит вывод, шлёт ввод.
  `Ctrl+\` (0x1c) — отсоединиться (сессия и телефон продолжают жить).
  `SIGWINCH` → отправка нового размера.
- `--device` TUI (`deviceTui`): список устройств, отзыв с подтверждением,
  переключение интернет-доступа, показ статуса p2p (число подключений, direct /
  relay, RTT).
- `--qr`: печатает QR (`{cb:1, host, port, code, fp}`) в терминал.

### 3.4 `stt.py` — распознавание речи (70 строк)

Постоянный воркер на `faster-whisper` (модель `large-v3`, CPU, int8, 8 потоков),
модель грузится один раз и держится в памяти. Протокол — JSON-строки stdin/stdout
(`{"file", "language"}` → `{"text"}` / `{"error"}`).

Особенности качества:

- **VAD-фильтр** (`vad_filter=True`, паузы <0.9 с не режут фразу) — главная
  защита от галлюцинаций Whisper на тишине.
- `initial_prompt` задаёт стиль с пунктуацией.
- Если длинный текст (>60 симв.) вернулся **совсем без знаков препинания**
  (известный сбой Whisper) — повторный проход с другой траекторией температур.

### 3.5 `hooks/bridge-hook.sh` — мост из Claude Code (11 строк)

POSIX-скрипт, вызывается хуками Claude Code. Вне bridge-сессии
(`$CLAUDE_BRIDGE_SESSION` пуст) молча выходит. Иначе `curl -sk --noproxy '*'`
шлёт событие (stdin) на `https://127.0.0.1:8790/hook` с заголовком
`X-Bridge-Session`. Таймаут 2 с, ошибки проглатываются (`|| true`) — хук никогда
не мешает работе Claude.

### 3.6 systemd-юнит

`~/.config/systemd/user/claude-bridge.service`: `Type=simple`,
`Restart=on-failure`, **`KillMode=process`** (важно: убивает только сам мост,
keeper-ы сессий переживают рестарт), `PATH` включает `~/.local/bin` (где живёт
`claude`).

## 4. Интернет-туннель `claude-tunnel` (каталог `tunnel/`, Rust)

Sidecar на Rust (`iroh 1.0.2`, QUIC). Один бинарь, три подкоманды. Собирается и
как нативный ПК-бинарь (`bridge/bin/claude-tunnel`, x86_64), и как Android-.so
(`libclaudetunnel.so`, aarch64) — Android запускает его как обычный процесс.
Профиль release: `opt-level="z"`, `lto`, `strip`, `codegen-units=1`.

ALPN протокола: `b"claude-bridge/1"`.

### 4.1 Подкоманды

- **`listen`** (сторона ПК): принимает iroh-соединения, каждый bi-stream
  пробрасывает на локальный TCP-таргет (`127.0.0.1:8792` — порт моста).
- **`connect`** (сторона телефона): локальный TCP-listener; каждое TCP-соединение
  форвардит как bi-stream по единственному (лениво устанавливаемому,
  авто-переподключаемому) iroh-соединению.
- **`id`**: печатает NodeId этого ключа и выходит (телефон так узнаёт свой
  постоянный NodeId для регистрации в allowlist). Важно: печатает **ровно тот**
  id, что предъявит `connect` (`endpoint.id()`) — на Android «короткий» путь из
  публичного ключа расходился с `endpoint.id()`.

### 4.2 Постоянный ключ (`load_or_create_secret`)

ed25519-ключ хранится в файле (`certs/iroh.key` на ПК, `files/iroh_phone.key` в
приложении). Логика чтения — усиленная (fail-closed, без TOCTOU):

- Файл открывается **ровно один раз** с флагом **`O_NOFOLLOW`** (симлинк →
  ошибка ELOOP): кража секрета = кража p2p-личности.
- Все операции (`stat`/`chmod`/чтение) идут **по этому fd**, а не по имени —
  подмена пути между проверкой и использованием исключена.
- Если права слишком открыты (`mode & 0o077 != 0`) — ужесточаются до `0600`
  через тот же fd (`fchmod`); **если ужесточить не удалось — отказ использовать
  ключ** (а не чтение как есть).
- Принимается как сырые 32 байта, так и hex (64 символа).
- Новый ключ создаётся `create_new(true).mode(0o600)`.

### 4.3 `listen` — сторона ПК

- **Fail-closed по умолчанию:** без `--allow-file` и без явного `--allow-any`
  слушатель **отказывается стартовать** — иначе он пробрасывал бы любой узел
  интернета на порт, дающий сетевое доверие.
- `endpoint.online().await` — ждёт готовности relays/discovery, чтобы ticket был
  полным; печатает `{event:"ready", ticket, node_id}`.
- Лимиты анти-амплификации: `MAX_CONNS = 32` (семафор), `MAX_STREAMS_PER_CONN =
  64` (семафор на соединение). Превышение — соединение/поток отбрасывается.
- **Таймаут рукопожатия 5 с:** slow-loris-пир иначе держал бы слот соединения до
  исчерпания лимита.
- **Транспортная авторизация:** `node_allowed()` сверяет `conn.remote_id()` с
  allowlist. Проверка — **при установке соединения И на каждый новый bi-stream**:
  если узел отозвали (мост переписал allow-file), новые потоки уже не пройдут и
  соединение закрывается. Отсутствующий/нечитаемый allow-file → **никого**
  (fail-closed).
- Каждый принятый stream → `TcpStream::connect(target)` + двунаправленная
  перекачка `pump`.
- `monitor_paths` следит за путями iroh (direct / relay / mixed, RTT) и шлёт
  события `path` — телефон показывает, как именно установлена связь.

### 4.4 `connect` — сторона телефона

- Парсит ticket → `EndpointAddr`; постоянный secret_file даёт стабильный NodeId.
- `ensure_conn`: одно общее iroh-соединение с backoff-переподключением
  (1 с → ×2 → максимум 15 с, таймаут dial 20 с), никогда не сдаётся.
- На каждое входящее TCP-соединение (от `LocalGateway`) — `open_bi`, до 5 попыток
  с инвалидацией мёртвого соединения, затем `pump`.
- `pump`: `tokio::io::copy` в обе стороны; TCP EOF → `send.finish()` +
  `stopped().await` (дожидается флаша); stream EOF → `shutdown` TCP-записи.

## 5. Android-приложение (каталог `android/`)

Пакет `com.q.claudebridge`, `minSdk 26`, `targetSdk 34`, без сторонних UI-фреймворков.
Зависимости: OkHttp 4.12 (TLS/WSS), Play Services code-scanner (QR). Нативный
UI собирается кодом (без layout-XML). Web-интерфейс терминала берётся из общего
`bridge/web` (Gradle-таски `syncWebAssets` / `syncVendorAssets` копируют его и
xterm в `assets/web` перед сборкой).

### 5.1 `MainActivity` — экраны и WebView (≈1160 строк)

Единственная активность (`singleTask`, `exported=true` для интентов из
уведомлений). Три состояния:

1. **Экран блокировки** (если включена биометрия и требуется вход).
2. **Экран сопряжения** (нет ни одного ПК).
3. **Основной экран** — WebView с терминалом.

#### Защита биометрией

- Флаг `biolock` в prefs. При включении:
  - `FLAG_SECURE` на окне — прячет содержимое из «недавних» и от скриншотов;
  - вход по `BiometricPrompt` (API≥28, `BIOMETRIC_WEAK | DEVICE_CREDENTIAL`) или
    `KeyguardManager.createConfirmDeviceCredentialIntent` (API 26/27).
- **Политика повторного запроса** (`needLock`): запирается, если после последней
  разблокировки **гас экран** (`screenOffSinceUnlock`, статик-флаг, ставит
  сервис по `ACTION_SCREEN_OFF`) **или** прошло больше `LOCK_GRACE_MS` (60 с)
  форы. Свежий процесс всегда запрашивает вход. Закрывает дыру «разблокировал →
  выключил экран → кто-то взял телефон в течение форы».
- Включить `biolock` нельзя без настроенной блокировки экрана
  (`km.isDeviceSecure()`).

#### Сопряжение

- **QR** (`startScan`, ML Kit): читает `{cb:1, host, port, code, fp}`. Отпечаток
  уже проверен вне канала → пиннится `expectedFp` сразу (`Tls.buildClient(fp)`).
- **Ручной код** (`pairByCode`): TOFU. Пиннится **фактический** сертификат
  рукопожатия (`Tls.capturingClient` пишет отпечаток в `seen`), а **не** значение
  из тела ответа — иначе MITM подтвердил бы собственный серт. Затем пользователь
  **сверяет 16 hex-символов отпечатка** с показанным в терминале ПК
  (`confirmFingerprint`).
- Цель ручного кода выбирается из найденных в сети несопряжённых ПК
  (`unpairedDiscovered`): один — сразу, несколько — диалог выбора.
- Итог сохраняется в `BridgeStore` (`commitPairing`), новый ПК становится
  активным, сервис переподключается, активность пересоздаётся.

#### Мост JS ↔ приложение

- **`AppBridge`** (`@JavascriptInterface AndroidApp`):
  - `openSettings()` — нативный экран настроек;
  - **`wsUrl()`** — `ws://127.0.0.1:<wsPort>/ws?cbnonce=<proxyNonce>`. **Токен в
    JS не отдаётся** — его подставляет нативный ws-прокси; странице достаётся
    лишь nonce запуска (допускает нас к прокси, но сам по себе бесполезен);
  - `copyText` / `pasteText` — системный буфер обмена.
- **`SttBridge`** (`AndroidSTT`): `start`/`stop`/`cancel`/`transcribe` — запись
  `MediaRecorder` (AAC/MP4, 44.1 кГц) в `cache/stt.m4a`, отправка на `/stt` с
  токеном, результат возвращается в JS (`window.sttResult`/`sttError`). Требует
  `RECORD_AUDIO`.

#### WebView — настройки безопасности

- JS включён, DOM-storage включён; **файловый доступ выключен**
  (`AllowFileAccess/ContentAccess/…FromFileURLs = false`) — страница локальная по
  http, доступ к ФС не нужен (защита в глубину).
- **`shouldOverrideUrlLoading`** (обе перегрузки): навигация допускается только
  на `http://127.0.0.1:<uiPort>`; любой другой адрес уходит во **внешний браузер**
  (`ACTION_VIEW`) и в WebView не грузится. Иначе недоверенная страница, открывшись
  здесь, через `AndroidApp.wsUrl()` выманила бы nonce прокси. Стартовая загрузка
  (`loadUrl`) и WebSocket сюда не попадают.
- **`onReceivedSslError`**: доверяем только сертификату с **запиннингованным**
  отпечатком (сверка `Tls.fingerprint(cert)` с `prefs.fp`), иначе `cancel()`.
- `onPageFinished`: если пришёл интент с `session`, дёргает `attach(...)` в JS;
  значение **экранируется** `JSONObject.quote` (защита от инъекции через интент).
- `onReceivedError` (main frame): показывает заставку и повторяет загрузку.

#### Прочее

- `validSession` — сессия из интента должна матчить `[A-Za-z0-9_-]{1,64}`
  (активность экспортируемая — чужое приложение не должно подсунуть мусор).
- `onBackPressed` — сворачивает (`moveTaskToBack`), не закрывает.
- `registerStateReceiver` — приём `ACTION_STATE` от сервиса; на API≥33
  `RECEIVER_NOT_EXPORTED`, на API<33 — защита signature-правом `INTERNAL_PERM`.

### 5.2 `BridgeService` — foreground-сервис (≈840 строк)

Постоянно живущий сервис (`foregroundServiceType=dataSync`). Держит WS с мостом,
находит мост в сети, показывает уведомления, управляет туннелем.

#### Обнаружение и выбор пути

- **mDNS (NSD)** + **UDP-проба** (broadcast `CLAUDE_BRIDGE?` на 8791). Найденный
  мост идентифицируется по `fp`: обновляется адрес нужного ПК; незнакомые ПК
  копятся в `discovered` для экрана «добавить компьютер».
- **Приоритет LAN.** `lanLastSeen` / `lanGraceUntil`: при старте и появлении WiFi
  даётся фора 12 с на поиск ПК в сети, прежде чем поднимать туннель. Если ПК
  давно (>15 с) не виден в LAN, а пользователь разрешил интернет для этого ПК и
  есть `nodeTicket` — поднимается туннель (`wantTunnel`). Если ПК снова появился
  в LAN, а мы на туннеле — форсированный реконнект на LAN (LAN важнее).
- `MulticastLock` удерживается ради mDNS.
- `registerDefaultNetworkCallback` — при появлении сети пробуем переподключиться.

#### WebSocket

- `connect()` идемпотентен; перечитывает prefs (активный ПК/токен могли
  смениться). Эффективный адрес пишется в `useHost/usePort` (их же читают WebView
  ws-прокси и загрузка аудио).
- URL: `wss://<host>:<port>/ws?token=<token>`; клиент — `Tls.buildClient(fp)`
  (пиннинг, ping 20 с).
- В `onOpen`: запрос `internet`-статуса и `registerNode` (сообщает мосту
  постоянный NodeId телефона).
- В `onMessage`: `notify` → системное уведомление; `status: working` → гасит
  устаревшее уведомление сессии; `sessions` → счётчик живых в статусе;
  `internet` → запоминает ticket ПК (`store.setTicket`).
- `onClosed(4401)` — устройство отозвано: удаляет ПК из списка, переключается на
  следующий.
- Backoff переподключения: 2 с → ×2 → максимум 30 с.

#### Постоянная p2p-личность телефона

- `ensurePhoneNodeId`: один раз запускает `libclaudetunnel.so id --secret-file
  files/iroh_phone.key`, парсит `node_id`, сохраняет в prefs. При наличии связи
  сразу регистрирует.
- `ensureTunnel(ticket)`: запускает `…connect --ticket=<value> --listen
  127.0.0.1:0 --secret-file <тот же ключ>`. `--ticket=<value>` одним аргументом,
  чтобы значение не спуталось с флагом (ProcessBuilder без shell). Парсит
  события `ready` (→ порт → `connect()`), `path` (обновляет UI/статус), `error`.

#### Уведомления и экономия батареи

- Два канала: `bridge_status` (IMPORTANCE_MIN, ongoing) и `claude_events`
  (IMPORTANCE_HIGH, вибрация, на локскрине `VISIBILITY_PRIVATE`).
- **Быстрый ответ** из уведомления (`ACTION_INPUT` → `ws.send` ввода в PTY, не
  открывая приложение). Кнопки «Да (1)», «Всегда (2)», «Нет (Esc)».
- **При биометрии** кнопки защищены: API≥31 — `setAuthenticationRequired(true)`
  (нажатие требует разблокировки), API<31 — кнопки не показываются вовсе; на
  локскрине контент скрыт (`VISIBILITY_SECRET`).
- Устаревшие уведомления гасятся: новое событие сессии заменяет прежнее,
  «Claude завершил ответ» (`Stop`) снимается при любом новом событии, ответ на
  ПК (`status: working`) снимает уведомление.
- **Режимы фоновой связи** (`bgMode`): `always` / `wifi` (в фоне только по WiFi)
  / `app` (только при открытом приложении). `allowedNow()` решает, держать ли
  связь; `pauseConnection()` рвёт её ради батареи.

### 5.3 `LocalGateway` — локальный шлюз для WebView (≈270 строк)

Делает интерфейс **всегда живым, даже когда ПК выключен**. Два TCP-сервера на
loopback (фиксированные порты для стабильного origin → `localStorage`
переживает рестарт):

- **`:38471` — статика** из assets APK (`index.html`, `app.js`, xterm…).
  Отдаёт с теми же CSP/защитными заголовками, что и мост; защита от `..` в пути.
- **`:38472` — ws-прокси**: прозрачный TCP-прокси до моста поверх TLS с
  пиннингом. Адрес моста берётся из prefs при **каждом** соединении (смена ПК /
  переход на туннель подхватываются сами).

**Модель безопасности прокси** (ключевая):

- Прокси на 127.0.0.1 доступен **любому** приложению на телефоне. Поэтому:
  1. **nonce запуска** (`proxyNonce`, 16 случайных байт): прокси обслуживает
     только запрос, содержащий `?cbnonce=<nonce>` (сверка **постоянного времени**,
     `MessageDigest.isEqual`). Nonce знает лишь наш WebView (через `wsUrl()`);
     чужое приложение подключиться не сможет.
  2. **Токен подставляется нативно** (`injectTokenCookie`): страница токен не
     знает, прокси дописывает `Cookie: bridgeToken=…` в апгрейд-заголовок перед
     форвардингом. XSS в UI не утащит токен — он не покидает нативную часть.
- `readHttpHead` читает заголовок побайтно до CRLFCRLF (лимит 16 КБ), не задев
  тело. `pump` перекачивает байты в обе стороны, TLS-сокет до моста —
  `Tls.socketFactory(fp)` (тот же пиннинг).

### 5.4 `BridgeStore` — реестр компьютеров (190 строк)

Список сопряжённых ПК в `SharedPreferences` (ключ `bridges` — JSON-массив).
Идентификатор ПК — отпечаток сертификата (`fp`). Поля `Bridge`: name, host, port,
token, fp, internet (флаг разрешения p2p), nodeTicket (iroh-адрес моста).

- **Активный ПК** (`activeFp`) определяет, куда подключаются сервис, WebView и
  загрузка аудио.
- **Зеркалирование:** плоские ключи `token/fp/port/host` всегда отражают активный
  ПК — «старый» код продолжает читать их как раньше.
- `migrate()` — старая схема (один ПК в плоских ключах) переезжает в список.
- Операции: `addOrUpdate`, `updateHost` (адрес найденного в сети), `remove` (при
  удалении активного активным становится первый оставшийся), `setActive`,
  `setInternet`, `setTicket`.

### 5.5 `Tls` — пиннинг сертификата (116 строк)

- `fingerprint(cert)` — SHA-256 hex от `cert.getEncoded()`.
- `pinnedTrust(fpHex)` — TrustManager, доверяющий **только** серту с данным
  отпечатком (`fpHex == null` → TOFU при сопряжении).
- `capturingClient(seen)` — для ручного сопряжения: доверяет любому серту, но
  **записывает фактический отпечаток** в `seen` (пиннить надо именно его).
- `socketFactory(fpHex)` — сырые TLS-сокеты с тем же пиннингом (для ws-прокси).
- `buildClient(fpHex)` — OkHttp с пиннингом; `hostnameVerifier` всегда true
  (доверие определяет **пиннинг**, а не имя хоста — сертификат самоподписанный на
  CN=claude-bridge, а адрес меняется).

### 5.6 Манифест и сетевой конфиг

- Разрешения: INTERNET, ACCESS_NETWORK_STATE, ACCESS_WIFI_STATE,
  CHANGE_WIFI_MULTICAST_STATE, POST_NOTIFICATIONS, RECORD_AUDIO,
  FOREGROUND_SERVICE(+DATA_SYNC), VIBRATE, USE_BIOMETRIC.
- **`INTERNAL_PERM`** (`signature`-уровень) — защищает broadcast сервис→активность
  от подделки чужим приложением на API<33.
- `allowBackup=false`, `fullBackupContent=false` — токены не утекают в бэкап.
- **`network_security_config`**: cleartext разрешён **только** к `127.0.0.1` /
  `localhost` (локальный шлюз), весь остальной cleartext запрещён
  (`base-config cleartextTrafficPermitted=false`). Связь с мостом всегда TLS.
- **jniLibs**: `useLegacyPackaging=true` — `.so` распаковывается, чтобы её можно
  было запустить как процесс (`exec`).

## 6. Web-интерфейс терминала (`bridge/web/`, общий для ПК и приложения)

`index.html` + `app.js` (≈830 строк) + `style.css`. Внутри приложения грузится
локально из assets; в браузере ПК — с моста. Определяет окружение по наличию
`window.AndroidApp`.

### 6.1 Терминал

- **xterm.js** (`@xterm/xterm` + `addon-fit`), тема тёмно-синяя, scrollback 10000.
- Ввод (`term.onData`) → `{type:'input'}`. Локальный экран **зеркалит фактический
  размер PTY** (сервер шлёт `resized`/`scrollback`); свой размер клиент лишь
  «предлагает» (`resize`), сервер применяет его, когда клиент печатает.
- `viewport()` считает cols/rows по фактическому размеру ячейки.

### 6.2 Прокрутка и выделение пальцем (самая нетривиальная часть)

- **Прокрутка:** обычный буфер (bash) — листаем scrollback xterm; альтернативный
  экран (Claude Code TUI) — шлём приложению **события колеса мыши**
  (`\x1b[<64…M`), TUI сам перерисовывает историю (`sendScroll` через тип
  `scroll`, чтобы не переключать «владельца размера» PTY).
- **Выделение:** долгое нажатие (500 мс) выделяет слово под пальцем, появляются
  два ползунка (`selh`), каждый тянется отдельно посимвольно. Жест
  перехватывается целиком (`preventDefault` на touchstart), иначе нативный
  long-press Android «съедает» палец.
- **Автоскролл у краёв** (`AUTOSCROLL_ZONE = 48`): выделение тянется вслед за
  прокруткой. В альтернативном экране, где историей владеет TUI, применяется
  эвристика `detectShift` — сравнивает снимки видимых строк до/после посланного
  колеса и сдвигает границы выделения на столько же строк, чтобы оно оставалось
  «приклеенным» к тексту.
- Копирование — через `AndroidApp.copyText` (или `navigator.clipboard` в
  браузере); вставка — в поле ввода.

### 6.3 Сессии, ввод, уведомления

- Вкладки сессий (`renderTabs`) с индикатором статуса (🟠 ждёт / 🔵 работает),
  долгое нажатие — завершить/убрать сессию.
- Панель клавиш (Esc, Tab, стрелки, Enter, ^C, вставка) + поле сообщения (Enter
  отправляет текст + `\r`).
- `notify` → баннер + вибрация + бип (`AudioContext`) + Web Notification (если
  вкладка скрыта).
- Диалог новой сессии: выбор проекта (из `projects`) или свой путь, чекбоксы
  `--resume` / `--dangerously-skip-permissions`.
- В приложении настройки устройств/компьютеров открываются нативным экраном
  (`AndroidApp.openSettings`), в браузере — WS-диалог `devices`.

### 6.4 Голосовой ввод в UI

Долгое нажатие (350 мс) на кнопку отправки → запись (`AndroidSTT.start`), таймер,
захват указателя (палец может дрожать). Отпускание → «Принять» (текст в поле) /
«Ввод» (сразу в Claude). Обработка — `AndroidSTT.transcribe`, результат приходит
в `window.sttResult`.

## 7. Протоколы (сводка)

### 7.1 WebSocket клиент ↔ мост (`/ws`, JSON)

**Клиент → мост:** `create` (cwd/command/args/title), `attach` (id/cols/rows),
`input` (id/data), `scroll` (id/data — не двигает владельца размера), `resize`,
`kill`, `remove`, `list`, `devices` (только local), `internet`, `registerNode`
(nodeId), `setInternet` (только local), `pairinfo` (только local), `revokeDevice`
(только local).

**Мост → клиент:** `sessions` (список + projects), `created` (id), `scrollback`
(данные/размер/alive), `output` (id/data), `resized`, `exit` (id/exitCode),
`status` (id/status), `notify` (id/event/message/title/at), `devices`,
`internet` (enabled/available/ticket/nodeId/peers), `pairinfo`, `error`.

Ограничение прав: `devices`, `setInternet`, `pairinfo`, `revokeDevice` работают
только для `ws.deviceId === 'local'` (сам ПК); телефон (`registerNode`) может
регистрировать только свой NodeId.

### 7.2 Keeper ↔ мост (unix-сокет, JSON-строки)

Мост→keeper: `in`, `resize`, `kill`. Keeper→мост: `hello`, `out`, `exit`.

### 7.3 Сайдкар туннеля → родитель (stdout, JSON-строки)

`ready` (ticket/node_id или port), `conn` (id/remote), `path`
(id/path/addr/rtt_ms), `close` (id), `id` (node_id), `error` (message).

### 7.4 HTTP-эндпоинты моста

`POST /pair` (код → токен, только осн. порт), `POST /stt` (аудио → текст,
`authed`), `POST /hook` (событие Claude, `isLocal`), `GET /health` (`authed`),
статика (`authed`).

### 7.5 UDP-обнаружение

Телефон → broadcast `CLAUDE_BRIDGE?` на `:8791`. Мост → unicast
`{claudeBridge, port, host, fp}` (только приватным адресам).

## 8. Модель безопасности (сводка)

| Угроза | Защита |
|--------|--------|
| Перехват трафика (MITM) | TLS с пиннингом SHA-256 отпечатка; hostname-verifier off, доверие только по отпечатку |
| MITM при ручном сопряжении | Пиннится фактический серт рукопожатия (не из тела ответа) + сверка отпечатка человеком; QR — отпечаток вне канала |
| Чужой процесс на ПК под видом «локального» | `isLocal` требует loopback + основной порт + совпадение UID через полный 4-кортеж /proc/net/tcp + ESTABLISHED; неопределимый UID → fail-closed |
| Кража токена через XSS в UI | Токен не попадает в JS: его нативно подставляет ws-прокси; странице — лишь nonce запуска |
| Чужое приложение на телефоне → мост через прокси | nonce запуска (сверка постоянного времени), известный только нашему WebView |
| Тайминг-атаки по токену/коду | `crypto.timingSafeEqual` / `MessageDigest.isEqual` |
| Перебор кода сопряжения | 5 попыток на IP → блок 15 мин; код одноразовый, TTL 10 мин |
| Запуск claude вне проектов с телефона | `remoteCwd`: realpath + allowlist каталогов; телефон не может задать произвольную команду |
| Любой узел интернета → порт моста | Туннель fail-closed без allowlist; allowlist NodeId сопряжённых устройств, перепроверка на каждый поток |
| Кража p2p-ключа / подмена пути | O_NOFOLLOW + операции по fd (без TOCTOU) + fail-closed при неудаче chmod; файл 0600 |
| DoS/амплификация через туннель | MAX_CONNS=32, MAX_STREAMS=64, таймаут рукопожатия 5 с |
| Исчерпание ресурсов моста | MAX_SESSIONS, rate-limit создания, лимит очереди STT, загрузка STT на диск с лимитом 20 МБ |
| UDP-маяк как рефлектор | Ответ только на приватные адреса (RFC1918/link-local/loopback) |
| Кликджекинг / инъекция скрипта | CSP-заголовок, X-Frame-Options, nosniff; экранирование значений из интентов (JSONObject.quote) |
| Утечка секретов на диске/в бэкапе | config/pairings/key/iroh.key — 0600, каталоги 0700; allowBackup=false |
| Доступ к содержимому с локскрина | FLAG_SECURE, биометрия с повторным запросом после гашения экрана, кнопки уведомлений с setAuthenticationRequired, VISIBILITY_SECRET |
| Подделка broadcast сервис→активность | RECEIVER_NOT_EXPORTED (API≥33) / signature-permission (API<33) |
| Открытие вредоносной ссылки в WebView | shouldOverrideUrlLoading запирает навигацию на локальный origin; чужие адреса — во внешний браузер |

## 9. Сборка и запуск

### 9.1 Мост (ПК)

```bash
cd bridge
npm install
node server.js          # или systemctl --user restart claude-bridge
```

Хук Claude Code (`~/.claude/settings.json` или проектный) должен вызывать
`bridge/hooks/bridge-hook.sh` на нужных событиях (Notification, Stop,
UserPromptSubmit, PostToolUse). Клиент на ПК — `claude-mobile` (обёртка над
`attach.js`).

### 9.2 Туннель (Rust)

```bash
cd tunnel
# ПК-бинарь (x86_64):
cargo build --release            # → target/release/claude-tunnel → bridge/bin/claude-tunnel
# Android (.so, aarch64) через NDK 28.2.13676358:
CC_aarch64_linux_android=…/aarch64-linux-android26-clang \
CARGO_TARGET_AARCH64_LINUX_ANDROID_LINKER=…/aarch64-linux-android26-clang \
cargo build --release --target aarch64-linux-android
# → jniLibs/arm64-v8a/libclaudetunnel.so
```

Замена занятого ПК-бинаря (процесс держит inode) — через `claude-tunnel.new` +
`mv -f` (атомарная замена, не трогает работающий executable).

### 9.3 Приложение (Android)

```bash
cd android
./gradlew assembleDebug     # preBuild синхронизирует web-assets и xterm из bridge/
./gradlew installDebug
```

Целевое устройство разработки: Xiaomi M2101K6G. adb/gradle — `~/Android/Sdk`.

## 11. Ключевые сквозные потоки

**Сопряжение по QR:** ПК печатает QR (`--qr`) → телефон сканирует → `POST /pair`
с пиннингом `expectedFp` → мост выдаёт токен/nodeTicket → сохранение в
BridgeStore → сервис подключается по WSS.

**Открытие терминала в приложении:** MainActivity грузит `http://127.0.0.1:38471`
из assets → app.js зовёт `AndroidApp.wsUrl()` → WebSocket на
`ws://127.0.0.1:38472/ws?cbnonce=…` → LocalGateway сверяет nonce, подставляет
токен, открывает TLS к мосту → мост шлёт `sessions`/`scrollback` → xterm рисует.

**Уведомление и быстрый ответ:** Claude Code → хук → `POST /hook` → мост
`broadcast notify` → BridgeService показывает системное уведомление → нажатие
«Да (1)» → `ACTION_INPUT` → `ws.send input` → keeper → PTY.

**Голос:** долгое нажатие «отправить» → `MediaRecorder` пишет m4a →
`AndroidSTT.transcribe` → `POST /stt` (токен) → stt.py (whisper) → текст → в поле
ввода или сразу в Claude.

**Уход из дома:** ПК пропал из LAN >15 с → BridgeService поднимает
`claude-tunnel connect` по сохранённому `nodeTicket` → iroh дозванивается до
`listen` на ПК (проверка allowlist по NodeId) → телефон подключается к
`wss://127.0.0.1:<порт туннеля>` → байты идут по QUIC на loopback-порт 8792
моста. Возврат в LAN → форс-реконнект на прямой путь.
